Public MarketLab

A distributed systematic trading lab built around two different machines with two different jobs: a Mac mini running Hermes Agent for collection, orchestration, research workflows, and paper-trading oversight, and a 5-card GPU rig for higher-throughput model training, ranking passes, and trading-side compute. The stack uses the Alpaca API for algorithmic paper trading while moving market research through a repeatable system that can collect, screen, evaluate, simulate, and accelerate experiments across dedicated hardware.

  • The Mac mini acts as the always-on research node: collecting stock, options, and crypto data, managing SQLite state, driving Hermes Agent-based workflows and reporting, and supervising Alpaca paper-trading operations.
  • Consistent database snapshots can be handed off to the GPU machine so the heavier training and ranking work runs where the compute actually lives, while Alpaca API paper positions and strategy state remain visible through the lab tooling.
  • The result is a private lab that behaves like an infrastructure system — with pipeline stages, telemetry, safety rails, and division of labor between orchestration hardware and compute hardware.

Operating Model Hermes Agent + Alpaca + GPU Separation

The lab is built around role separation: Hermes Agent and the Mac mini keep research organized, persistent, and tied to Alpaca paper-trading workflows, while the GPU rig takes on the heavier numerical work when it is time to train, rank, or test at scale.

Architecture

How the two-machine workflow is structured

The architecture is intentionally split. The Mac mini side continuously collects public market data, maintains the local SQLite dataset, drives Hermes Agent-powered research and reporting workflows, and coordinates Alpaca API paper-trading activity. When there is enough history to do meaningful training or broader ranking work, a consistent snapshot of the database is moved to the 5-card GPU rig, where the heavier experiments run without interrupting the collector. That separation keeps the system practical: one node is stable and always-on, the other is optimized for bursty compute.

01 / Research Node

Mac mini handles collection and orchestration

Public stocks, delayed options chains, and crypto ticker data are gathered continuously while Hermes Agent coordinates reporting, research flow, repeatable operator tasks, and the paper-trading side of the Alpaca workflow.

02 / Handoff

SQLite snapshot transfer preserves consistency

Instead of sharing a live mutable database between machines, the project uses safe local snapshots so the GPU side can train against a coherent dataset copy.

03 / Compute Node

5-GPU rig handles the expensive passes

Higher-throughput model training, ranking experiments, and GPU-heavy analysis jobs are pushed onto the rig designed for them rather than the orchestration node.

Functionality

What the system actually does

Collection + Storage

Local dataset over time

  • Collects market snapshots into SQLite as a durable local research dataset.
  • Keeps the time-ordered history needed for screening, simulation, and training readiness.
Screening + Risk

Deterministic filters plus Alpaca paper execution

  • Screens candidates through transparent momentum, liquidity, spread, delta, and premium constraints before promoting ideas into the paper-trading workflow.
  • Uses the Alpaca API for paper positions while tracking invested capital, current value, and unrealized P&L through the lab ledger and dashboard.
Telemetry + Ops

Operational visibility built in

  • Flask dashboard surfaces candidates, P&L, database health, training readiness, recent runs, and GPU telemetry.
  • The project is described and operated like an infrastructure platform, not a one-script bot.
