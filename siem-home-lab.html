Detection Engineering

SIEMHome Lab

A self-contained security operations lab built on VMware, where a small Windows Active Directory domain sits behind a pfSense firewall and feeds host, identity, and network telemetry into Splunk. The lab exists to do one thing well: generate realistic attacker behavior, capture the right logs, and turn that data into working detections — the full loop from raw event to alert.

  • Windows Server runs Active Directory and Group Policy, with domain-joined Windows clients producing real authentication, account, and policy events.
  • Sysmon and Windows Event Forwarding ship endpoint and identity telemetry into Splunk, building a centralized view of host and login activity across the domain.
  • Attacks are simulated on purpose — brute force, account lockouts, and privilege escalation — then each one is detected with a purpose-written Splunk search so the lab proves detection, not just collection.

Operating Model Collect → Attack → Detect

The lab is built as a closed detection-engineering loop: forward the right telemetry into Splunk, run deliberate attack scenarios against the domain, then write and validate searches that catch each behavior in real time.

Architecture

How the lab is wired together

Everything runs as virtual machines on a single host under VMware. A pfSense VM sits at the edge and segments the internal lab network from everything else. Inside that network, a Windows Server domain controller runs Active Directory and Group Policy, with domain-joined Windows clients generating day-to-day authentication and account activity. Sysmon and Windows Event Forwarding push endpoint and identity events into a Splunk instance, which becomes the single place to search, correlate, and alert on what happened across the domain.

01 / Domain

Windows Server + Active Directory

A domain controller provides AD authentication, Group Policy, and OU structure, while domain-joined clients produce realistic logon, account, and policy-change events.

02 / Telemetry

Sysmon + Event Forwarding

Sysmon enriches endpoint visibility with process, network, and registry events, and Windows Event Forwarding centralizes host and identity logs for ingestion into Splunk.

03 / Analytics

Splunk index and search

All forwarded data lands in Splunk, where saved searches and dashboards turn raw Windows and Sysmon events into detections, timelines, and investigative views.

Detections

Attacks simulated, then caught

Each scenario follows the same discipline: run the attack against the domain, confirm the expected events land in Splunk, then write a search that isolates that behavior reliably. The goal is detection logic that maps to specific Windows security event IDs rather than vague noise.

Brute Force Logons EventCode=4625 | stats count by src_ip, user | where count > threshold
Account Lockouts EventCode=4740 | stats count by user, ComputerName | sort - count
Privilege Escalation EventCode=4672 OR EventCode=4728 OR EventCode=4732 | table _time, user, Group_Name
Suspicious Process Activity source="WinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1 | stats count by ParentImage, Image
